# 执行纪律与硬规则

> 项目开始前必读；批量任务前复习。历史决策见 `parts/decisions-log.md`。

---

## 🔥🔥🔥 爆款第一原则（覆盖所有其他规则）

> **每秒都有情绪。** 规则与"这秒观众看什么"冲突时，以观众情绪为准。
> 短剧精髓是**简单粗暴有效**，不是精密工程。情感陪伴 > 剧情深度，声音是付费驱动因素。

## 一、生成策略硬规则

### 1.1 叙事层/制作层分离

| 任务类型 | 策略 | 理由 |
|----------|------|------|
| **剧本生成** | 主模型逐集 write_file（串行） | 叙事连续性是底线 |
| **分镜生成** | 主模型批量 write_file（剧本定稿后） | 分镜间无叙事依赖，2-3集合并最佳 |
| **Prompts 生成** | 主模型批量 write_file（分镜定稿后） | 分镜已定，可批量 |
| **Review 审核** | 主模型直接做 | 多集审查子代理必超时 |
| **单集精修** | 主模型 write_file | 子代理不值得启动开销 |

### 1.2 子代理唯一适用场景
- 代码脚本编写（generate_index.py, build_html.py）
- 视频生成任务（Dreamina/Seedance API，可异步+notify）
- 独立推理任务（单集质量分析、竞品对标）

### 1.3 批量任务执行纪律

**强制规则**：10+ 集批量生成前，先输出执行计划（方式+预估时间+分批策略），等用户确认后再执行。

**阶段5（批量分镜）**：前置检查(TASK.md确认定稿) → 2-3集合并写入 → 批量审核 → FAIL集统一修改
**阶段6（批量Prompts）**：同上，额外检查风格词一致性（每集第一个Prompt风格词不应漂移）

### 1.4 数据提取策略

**强制规则**：剧本对白/VO/Cliffhanger 提取**只用主模型逐集精读**，不调正则脚本，不让子代理跑。

**32集以上批量生成**：不用本地模型API循环调用，改用主模型逐集write_file。

### 1.5 硬性规则

1. **审核不可跳过** — 每集Aligner审核≥80分才过。质量基线稳定后（3+集通过）可接受1轮快速审核
2. **每集输出预算** — 一集完整三件套+审核≈15-17K tokens
3. **主Agent逐集是默认方案** — 实测20+集无问题
4. **中断恢复** — 用 `ls script/ storyboard/ prompts/` + `stat` 确认实际完成进度
5. **continuity更新** — 每集必更核心三项（Cliffhanger/伏笔操作/角色状态，轻量追加）；全文件整理压缩每3集一次；EP-20+后只保留活跃伏笔
6. **Review可内联** — 审核结果可内联到Script文件末尾，节省1个write_file

### 1.6 子Agent上下文压缩（如必须用）

```
好（~5K tokens）：
- continuity.md（核心：进度+伏笔+角色状态）
- outline.md 对应集梗概（只读相关段落）
- characters.md 本集出场角色的 base_prompt
- manifest.md 色调规则（当前幕）

坏（30K+ tokens）：读所有文件全文
```

## 二、Beat Engine — 欧美爆款核心结构

> 每集按 **Hook → Friction → Spike → Button** 四段写。先写timestamp skeleton，再写对白承载。结构先行，语言后行。
> ⚠️ **四段是功能，不是秒表**：时间戳是默认骨架；单场连续对峙集（从头吵到尾）允许结构上不可切分，但四个功能（引爆/可拍摄冲突/重定价/切断）必须齐备——审核按功能查，不按时间戳扣分。

| 段 | 时间 | 作用 | 硬规则 |
|---|------|------|--------|
| **Hook** | 0-15s | 引爆 | 3秒定帧：陌生人不需要前情就能理解画面 |
| **Friction** | 15-60s | 引擎室 | 必须是**可拍摄的冲突**（物理/语言），不是情绪暗示 |
| **Spike** | 60-85s | 最大冲击 | 重新定价之前所有信息；静音测试：静音后spike消失=不是spike |
| **Button** | 最后5-10s（从Spike尾部切出） | 悬念切断 | 在问题前切断，不是答案后。比感觉安全早2秒 |

**AI常犯错误**：
- ❌ Hook写成铺垫 / Friction写成情绪暗示 / Spike依赖音效 / Button解释太多

## 三、Premise-Driven Conflict — 冲突内建于设定

> 冲突必须**内建于premise**，不是场景制造。90秒一集，没有时间逐场制造障碍。

**已验证的爆款Premise（示例表，不是白名单）**：

| Premise | 自动产生冲突原因 | 适用类型 |
|---------|-----------------|----------|
| **Enemies-to-lovers** | 角色天然对立 | revenge, forced_love |
| **Forbidden proximity** | 被迫共处但不该在一起 | forced_love, mystery |
| **Power imbalance** | 权力不对等 | forced_love, mary_sue |
| **Arranged/forced circumstance** | 非自愿连接（含契约婚姻 Marriage of convenience） | forced_love, revenge |
| **Fated mates / Rejected mate** | 命定纽带被拒绝/背叛，张力内建于设定 | vampire_werewolf |
| **Second chance / 离婚开局** | 旧关系破裂后被迫重逢，旧债即张力 | revenge, sweet_romance |
| **Secret baby** | 隐藏的孩子=行走的定时炸弹信息差（天然DI） | forced_love, sweet_romance |
| **Victim's return** | 受害者带新身份归来，每次同框都是清算倒计时 | revenge, mary_sue |

**Premise自检（唯一判据）**：角色只要同框就有张力→合格；需要每场戏制造障碍→重做。上表是已验证示例，命中判据但不在表内的 Premise 同样合格。

## 四、Dramatic Irony — 最强留存机制

> 观众知道角色不知道的事。与 cliffhanger **互补**的留存机制：卡点转化靠 cliffhanger，跨集粘性靠 DI（secret baby/隐藏身份类全靠它）。

**实操规则**：
1. EP 2-3 建立观众信息优势
2. 维持差距：角色接近真相又拉回，持续多集
3. 每集至少一个"观众知道但角色不知道"的时刻
4. 揭秘时机 = 付费墙后

**AI常犯错误**：只用伏笔 / 角色太快发现真相

## 五、对白=行动

> 每句对白要么推进冲突，要么压力下揭示角色。两者都不做→删。

1. **角色不解释感受** — 行动、否认、转移。观众推断
2. **Subtext > Text** — 没说的比说了的更有力
3. **冲突前2行进入** — 中性开场2-3行内暗流浮现
4. **竖屏对白短促** — 长独白极少有效
5. **静音测试** — 对白静音后场景失去意义=画面没在干活

## 六、AI炫技防控（五大陷阱）

| # | 陷阱 | 硬规则 | 违反后果 |
|---|------|--------|----------|
| 1 | 分镜过度工程化 | 按集类型分层精度（见templates.md） | 浪费token+稀释冲击力 |
| 2 | 运镜炫技 | 🟡≤2个/集+必须写理由 | 无理由🟡=炫技扣分 |
| 3 | 钩子等级通胀 | 能用单一的不用复合，能用低级的不用高级 | 非高潮集用复合钩子→-5分 |
| 4 | 过度合规化 | 核心冲击力(12分)最高权重 | 合规但无聊=不及格 |
| 5 | continuity膨胀 | 生成时只读3项核心（Cliffhanger+到期伏笔+角色状态） | 伏笔管理焦虑>爽点制造 |

## 七、竖屏与声音硬规则

### 竖屏特写优先
- 特写/近景≥50%，全景/中景≤30%（仅定场/转场）
- 核心情绪在面部微表情传达

### 声音/BGM是付费第一驱动
- BGM随Beat Engine变化（Hook引爆/Friction强化/Spike静音/Button骤停）
- SFX强化可拍摄动作
- Button前BGM骤停→观众脑补
- BGM无理由持续=浪费付费驱动因素
