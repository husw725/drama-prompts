### 🔥 v2.4 关键变更：按集串行，不再并行

**为什么必须串行？**（2026-05-10 验证结论）

多子Agent并行生成的致命缺陷：会话隔离、悬念丢失、角色状态漂移、伏笔无人回收、冲突模式重复。

**串行生成的优势：**同一Agent会话完整上下文记忆，精确承接悬念和情绪，伏笔追踪确保回收，冲突模式自然升级。

### 🔥 v3.8 关键变更：叙事层与制作层分离

> 串行的必要性只存在于**叙事层**（剧本），不存在于**制作层**（分镜/Prompts）。
> 分镜间无叙事依赖——EP-03的分镜不需要知道EP-02的分镜，只需要知道EP-03的剧本。
> 实际工作流中剧本通常需要反复修改调整——"写完一集剧本→立刻生分镜"是理想化假设。
> 分离后，剧本修改不会导致分镜/Prompts级联重做。
> 提速估算：12集项目从54min→34min（~37%）。

### 阶段 4：叙事层 — 逐集剧本串行（v3.8 ⭐ 核心阶段）

> **唯一必须串行的阶段。** 剧本叙事连续性不可妥协。剧本写完后进入人工确认，可反复修改调整，直到定稿。

**每集执行流程：** 读取continuity.md → 编剧write_file → Script-Aligner审核 → 更新continuity.md → 下一集

  ✅ 全部剧本完成 → 人工确认/修改/定稿 → 进入阶段 5

### 阶段 4a：全剧骨架串行生成（v3.9 ⭐ 提速方案）

> **核心思路**：大纲阶段已规划了每集的集定位+大纲承诺+叙事预算+关系转折点，剧本生成可以从"从零创作"变为"骨架填充"。骨架是比大纲更细、比剧本更粗的中间层，预先生成后经人工确认，剧本阶段只需填充对白/动作/细节。

> **连续性保障（底线 ⚠️）**：骨架**必须串行生成**，和完整剧本一样严格保证连续性。每集骨架生成前必须读上一集骨架的结尾（Cliffhanger+伏笔操作+关系状态变化），确保叙事链条不断。

**骨架格式（每集~300字）**：
```markdown
### EP-04 骨架
- **集定位**: 转折集
- **开篇承接**: Laura触摸发光咬痕（回收EP-03 Cliffhanger）
- **核心事件**: Carmilla部分揭示身份——她不是人类，但不是普通吸血鬼
- **冲突**: 信息争夺（Laura逼问 vs Carmilla闪避）→ 不可逆代价：Carmilla为证明身份展示力量，打碎古堡石柱
- **关系转折**: Laura×Carmilla 从好奇→危险暧昧（触发：Carmilla展示力量时流露脆弱）
- **伏笔操作**: 回收F-01（咬痕发光=吸血鬼标记）；新埋F-07（石柱碎裂露出密室入口）
- **大纲承诺兑现**: ✅ Carmilla身份部分揭示 ✅ 咬痕秘密回收
- **Cliffhanger**: 密室入口暴露，里面传来钟声（异常钩子2+信息钩子1）
- **叙事预算**: 新伏笔1个 / 新信息点2个 / 新角色0个
```

**骨架生成流程（串行 ⚠️）**：
```
for EP in [EP-01, EP-02, ..., EP-N]:
  1. 读 continuity.md（当前伏笔/角色状态/冲突模式/叙事预算）
  2. 读 outline.md 对应集（集定位+大纲承诺+叙事预算）
  3. 读 outline.md 类型DNA（冲突升级模式/钩子偏好/禁忌模式）
  4. 读 characters.md 关系动力学（本集关系转折点）
  5. 读 continuity.md 付费墙策略
  6. 读 上一集骨架结尾（Cliffhanger+伏笔操作+关系状态）— 保证连续性
  7. 生成骨架 → 写入 skeleton/EP-XX.md
  8. 更新 skeleton_continuity.md（骨架级连续性追踪）
  → 下一集

✅ 全部骨架完成 → 人工确认/修改 → 进入阶段4b（剧本填充）
```

**骨架 vs 完整剧本的区别**：
| 维度 | 骨架 | 完整剧本 |
|------|------|----------|
| 对白 | 无 | 完整对白+动作描述 |
| 场景 | 只写场景名 | 完整场景描写 |
| 时长 | 无 | 70秒分配 |
| 连续性 | ✅ 完整（Cliffhanger+伏笔+关系） | ✅ 完整 |
| 体积 | ~300字/集 | ~3000字/集 |
| 生成速度 | ~10s/集 | ~30-60s/集 |

**阶段4b：剧本填充（基于骨架）**：
```
for EP in [EP-01, EP-02, ..., EP-N]:
  1. 读 skeleton/EP-XX.md（骨架）
  2. 读 continuity.md + 上一集剧本结尾
  3. 按"骨架→剧本"填充对白/动作/场景描写/时长分配
  4. Script-Aligner审核（含大纲承诺兑现检查）
  5. 更新 continuity.md
  → 下一集
```

> **提速原理**：骨架生成~10s/集（vs 剧本30-60s/集），12集骨架~2min。剧本填充时约束更明确（骨架已确定冲突/转折/伏笔），生成更快且重写概率更低。预估总提速30-40%。

> **连续性保障总结**：骨架串行生成 + 每集读上集骨架结尾 + skeleton_continuity.md追踪 + 人工确认后填充。连续性和逐集生成完全等价，只是把"创作"和"填充"分开。

### 阶段 5：制作层 — 批量分镜（v3.8 ⭐ 含 Director's Treatment）

> **前提**：所有剧本已定稿。分镜间无叙事依赖，可批量生成。

**阶段 5a：Director's Treatment**（每集1页，~500字：视觉策略+情绪弧线+Hero Shots+运镜策略+节奏策略）→ 人工确认

> **Treatment 视觉衔接声明（v3.9 ⭐ 新增）**：每集 Treatment 开头必须声明与上集的视觉衔接关系，格式：
> `## 视觉衔接：承接EP-XX结尾 — [色调]/[场景]/[角色位置]/[主光源]`
> 示例：`## 视觉衔接：承接EP-02结尾 — 冷蓝灰色调/卧室门半开/Carmilla画面右侧/烛火残光为主光源`
> 作用：导演一眼看衔接关系；分镜生成时作为视觉约束参考

**阶段 5b：执行分镜**（基于Treatment，2-3集合并最佳，**链式批量 ⭐ v3.9**）→ Storyboard-Aligner批量审核 → FAIL集统一修改

> **链式批量（v3.9 ⭐ 新增）**：每批分镜生成前，必须读取上一批尾集的分镜 + `visual_continuity.md`，确保视觉风格/色调/运镜不漂移。
>
> **链式读取规则**：
> - 第1批（EP-01~03）：读 visual_continuity.md（如有）+ Treatment
> - 第2批（EP-04~06）：读 EP-03 分镜 + visual_continuity.md + Treatment
> - 第N批：读上一批尾集分镜 + visual_continuity.md + Treatment
> - 额外开销：每批多读1集分镜(~3-5KB) + visual_continuity.md(~1-3KB)，对主模型上下文无压力

  ✅ 全部分镜定稿 → 人工确认 → 进入阶段 6

### 阶段 6：制作层 — 批量 Prompts（v3.8 ⭐）

> **前提**：所有分镜已定稿。Prompts可批量生成，2-3集合并最佳。

批量生成 → Prompt-Aligner批量审核 → FAIL集统一修改 → 人工确认 → 进入阶段 7（工作台生成）

> **分镜读取上下文（每集）**：script/EP-XX.md + characters.md + manifest.md + scene_prop_data.json + `visual_continuity.md`（上一集结尾视觉快照 ⭐ v3.9）

> **v3.9 变更**：原"上一集分镜最后2镜"升级为读取 `visual_continuity.md` 中的上一集结尾视觉快照。信息量从2镜扩展到完整画面状态+色调+运镜+服装+场景物理+光源方向，且体积仅~200字/集，不增加上下文负担。

### 🔥 continuity.md — 剧集连续性追踪文件

> **这是 v2.4 最核心的新增文件。** 它是连接集与集之间的"叙事记忆"，确保每一集都知道之前的故事状态。

**文件格式：**

```markdown
# 剧集连续性追踪 (Continuity Tracker)

> 自动生成，每集更新。下一集编剧开始前必须读取此文件。

---

## 当前进度
- **已完成**: EP-01, EP-02
- **进行中**: EP-03
- **总集数**: 12 集

## 付费墙规划（v3.8 ⭐ 新增）
