## 常见陷阱

| # | 陷阱 | 解决 |
|---|------|------|
| 1 | 跨集衔接断裂 | 每集写完检查下集开场是否回收 |
| 2 | 标准过于模糊 | 量化评分 + 具体扣分理由 |
| 3 | 套用公式审分镜 | 先判断集类型，再动态评估 |
| 4 | 对英文剧名用国内人设 | 先确认市场，再切换人设 |
| 5 | 悬疑强剧情路线 | 海外观众"不花钱也能忍" |
| 6 | 忽略声音 | 声音是海外用户付费的核心驱动因素 |
| 7 | Hook 写成铺垫 | 3秒定帧：陌生人不需要前情就能理解画面 |
| 8 | Friction 写成情绪暗示 | 必须可拍摄：物理/语言冲突，不是"气氛紧张" |
| 9 | 场景驱动冲突 | Premise自检：设定是否自动产生冲突？ |
| 10 | Dramatic Irony 缺失 | EP2-3必须建立观众信息优势 |
| 11 | 对白解释感受 | 行动/否认/转移，观众推断 |
| 12 | 全景过多 | 竖屏=特写优先，特写/近景≥50% |
| 13 | Button 解释太多 | 在问题前切断，比安全早2秒 |
| 14 | 忽略付费墙卡点 | 情绪高峰是否踩在EP8/10卡币位置 |
| 15 | 无广告素材爆点 | 全剧是否有3-5个可切广告的高能切片 |
| 16 | 恋爱脑/雌竞无独立线 | 女主遭遇背叛时是否有独立选择 |
| 17 | Chinglish/文化水土不服 | 台词本地化自然度+配音表现力 |

## 审核通过关键要素

> 核心法则详见 `pitfalls.md`（Beat Engine + Premise + DI + 对白=行动 + 炫技防控）

### 必须通过项
1. **Beat Engine 四段完整** — Hook引爆/Friction可拍摄/Spike静音测试/Button切断
2. **Premise 自带冲突** — 4种Premise之一，非场景驱动
3. **Dramatic Irony 活跃** — EP2-3建立观众信息优势，差距维持到付费墙后
4. **对白=行动** — 冲突前2行进入，角色不解释感受，Subtext>Text

### 对白=行动
- ✅ 冲突前2行就进入，角色不解释感受，Subtext>Text

### 典型迭代次数
- **EP-01**: 3次（建立冲突模式+Premise验证）
- **EP-02**: 4次（建立人物关系+DI信息优势）
- **EP-03 后**: 2-3次（模式已建立）

## 三件套实战教训

| 翻车点 | 表现 | 修复 |
|--------|------|------|
| 核心关系缺席 | 零出场/零台词/零情绪关联 | 加入闪回+矛盾心理台词 |
| 开局依赖上集回收 | 前3秒只是"上集闪过" | 改为主动视觉冲击开场 |
| 冲突无不可逆代价 | 闪避/自然扩散 | 撕毁关键页等永久性损失 |
| 对白过多 | 19句/集 | 压缩到12-15句，每句有信息量 |
| 角色外观漂移 | 瞳色集间变化 | manifest.md 强制锁定 |

**分镜硬规则（写前检查）**：
- 镜头数按集类型：氛围16-18 / 标准18-22 / 恐怖20-24 / 高潮22-25
- 单镜≤5秒，正面镜头≤35%
- 运镜种类≥5种，对白12-15句/集

**效率技巧**：
- 写分镜前先在脚本中标注每个time slot的scene和action
- 审核FAIL时重写：保留通过部分，只修改扣分项对应段落
